# Glossary

- **game project** — the unit the studio is organised around: a chat thread plus a versioned working tree of files, playable at a public URL. A `projects` row with `kind = 'game'`. (formerly: *conversation*, in `new-y`)
- **chat project** — a `projects` row with `kind = 'chat'`: no working tree, nothing on disk, nothing served on the games origin. It has *chats* like any project; they are simply all it has. (formerly: chat, before a project could hold several conversations)
- **tint** — the per-speaker colour wash on a message bubble. Hue and blob placement are derived from a hash of the speaker's id, warm for people and green-to-blue for agents; it carries no meaning beyond identity.
- **slug** — a project's `[a-z0-9-]` identifier. Immutable, and simultaneously the directory name under `GAMES_DIR` and the path segment on the games origin.
- **working tree** — a project's on-disk directory. The source of truth for file content; there is no files table.
- **project path** — a validated relative path inside a working tree. Validation rules are the app's main security boundary.
- **studio access** — presence of a row in `users`. It is what gets you in, and it lets you *read* everything: every game, every version, every conversation. What it no longer carries is the right to change somebody else's game — see *author*.
- **author** — somebody who may change a game: the person who made it, plus anyone an author has added (`project_authors`). A game keeps at least one. An author decides who else is one, and whether the game is *open* — being able to work on a game is not the same as deciding who does. Two things sit outside the rule on purpose: anybody in the studio may talk in a game's human-only *chat*, and anybody who can read a game may *fork* it.
- **open** — `projects.open_edit`: this game is the whole studio's to change. Off by default and set by an author, because a game everyone can edit should be a decision rather than what happens when nobody was added.
- **studio origin** — the authenticated listener (`PORT`) serving the SPA and `/api`.
- **games origin** — the unauthenticated listener (`GAMES_PORT`) serving only game files. A separate origin so LLM-written game code cannot read a studio response. On two ports of one hostname the session cookie still travels there, so it is a read boundary, not a write one — spec.md §7.
- **config file** — a file under `config/` in a game's working tree: plain `const NAME = value;` declarations with a comment on every value, holding the numbers and words a person tunes without reading code. One batch per file — `play.js`, `world.js`, `look.js`, `words.js`, `controls.js`. Loaded by the game like any other script; agents may change them freely, keeping the comments.
- **pixel editor** — how a PNG opens in the pane: the picture itself, ready to draw on, with Draw, Erase, Fill and Eyedropper as icons, a brush width, a *palette*, and undo and redo a gesture at a time — each step holding the pixels it changed rather than a copy of the picture.
- **look** — the four colours a game lends the studio, named in `LOOK` in its own `config/look.js`: `primary` (the game's voice — its buttons, its name, your own messages), `accent` (the second colour: helper names, file chips, edges), `highlight` (a score or a version number, and nothing else) and `deep` (the dark behind them). Set on the shell as `--look-primary` and friends while that game is open, so the chat pane, the composer, the *actions drawer* and the rail wear the game being made; the sidebar keeps the studio's own cyan, which is what stops the studio from looking like whichever game is open. ⚠️ Each value reaches a style attribute, so it is checked first — no colon, semicolon, `url()` or `var()` — and a value that fails leaves the studio's default standing. Same file as the *palette*, read in the same pass.
- **actions drawer** — what you can do to a whole game — make a copy, put it in or take it out of the games list, rename — folded away under the game's name in the chat bar, and open from any tab. `.acts`, opened by the title itself (`aria-expanded`), closed when the game changes. It replaced the foot of the Play tab, which put these under a preview of a game you were playing and out of reach everywhere else.
- **palette** — `PALETTE` in a game's `config/look.js`: thirty-two colours, two rows of sixteen, that the *pixel editor* offers. Not a fixed list — the chosen square is both what the pencil draws with and what the colour box and the eyedropper write into, so it is built up rather than picked from, and each change is a commit on the game. A game with no `look.js` is shown the studio's own thirty-two, and the first change writes the file. The only way a PNG opens — there is no second, look-only view, because it showed the picture at exactly the same size. Up to 1024 a side, RGBA rather than a palette of indexes, so an uploaded picture opens losslessly and is saved at the size it arrived.
- **sound editor** — how a `.wav` the studio wrote opens in the pane: a preset, a shape, and a row of sliders with a comment on each, saved back over the same file like any other *asset*. The same surface makes a new sound and changes an old one, because the file carries its own *sound note*; `+ Make a sound` asks nothing at all — it writes a blip into `assets/sounds/` under a name nobody has to think of and opens it, because the name is a better question once you have heard it. Plain arithmetic in `public/sound-maker.js` — no Web Audio — so the bytes it plays are the bytes it saves. A sound from anywhere else opens as the player, with the reason underneath. (formerly: sound maker, which was a dialog.)
- **sound note** — the numbers that made a sound, written into the `.wav` they made: a JSON comment in the file's `LIST`/`INFO`/`ICMT` chunk, which every player skips and an audio editor shows. It is what makes a sound editable a week later — samples cannot be turned back into sliders — and it travels with the file through a rename, a copy or a clone, which a note beside the file would not. Nothing in it is trusted: a value no slider could produce is the default instead.
- **studio library** — the studio's own code, copied into a game under `studio/` and listed in its **manifest**, `studio/studio.json`, as name-to-version. Copied rather than shared or submoduled so the repository stays complete: clone it, publish it, and it still runs. Two rules make it a library — ⚠️ a helper may read it and never write it (`isLibraryPath` in `paths.js`), and it is named to an agent rather than sent, so an engine costs the ambient context a line instead of its source. The *input module* is the first one. Every game is born holding the library — creation scaffolds it in one commit — and keeps the version it was born with: there is no update from inside the studio, and bringing an older game forward is a sweep across the game repositories (`deploy/sync-games.sh`). See spec.md §4.
- **game template** — a starter tree copied into a new game at creation ("Start from" in the New game dialog): a whole small game with its remixable heart in a config file, a pre-written *brief* and *game spec*, and the library tags already in place. From then on the files are the game's own — no version, no updates, editable everywhere — unlike a *studio library*. Source: `public/game-templates/` (distinct from `public/templates/`, the library seeds). The quiz is the first. See spec.md §4.
- **quiz editor** — how `config/questions.js` opens while it keeps the quiz shape: the whole game as a form — questions, answers wired to endings, endings — no code shown. Regenerates the file rather than splicing (it is that file's authoring surface; byte-identical on an untouched save), and falls back to the *config form*, then the text, once the file outgrows the shape. Ending keys are internal wiring, never shown.
- **sprites library** — `studio/sprites.js`, the third *studio library*: `Sprites.draw(ctx, "hero", x, y)` draws `assets/sprites/hero.png`, animated when the file is a *strip*, with `scale`, `flip`, a pinned `frame`, and a shared clock advanced by `Sprites.tick()`. No registry: the name is the file, the shape of the picture is the declaration. Still loading draws nothing; missing warns once.
- **strip** — a PNG whose width is a whole multiple of its height: square frames side by side in one file, played in order by the *sprites library*. Made by `+ Draw a picture` with a frame count, or uploaded. Opens in the *pixel editor* one frame at a time — frame buttons, a live looping preview, Copy/Paste frame, a toggleable **ghost** of the frame before, tools clipped to the open frame — with "Whole strip" to draw across everything under a frame-boundary overlay. Any other shape is a single picture.
- **sound player** — `studio/sound.js`, the second *studio library*: `Sound.play("laser")` plays `assets/sounds/laser.wav` — what the *sound editor* saves — with a pooled player per shot so rapid fire overlaps instead of dropping, plus `loop`, `stop` and `mute`. A missing file or a blocked autoplay is one console warning, never an error. Its API note is its file header.
- **input module** — `studio/input.js` in a game's working tree, the first *studio library*: one way in for the keyboard, a game controller and a touchscreen, for one player or two. `Input.update()` once a frame, then `held`, `pressed`, `released`, `axis`. Unlike the *reporter* it is a file the game carries — added from the studio, in the history, cloned with the repo — and what each button does lives in `config/controls.js`, which is the game's own *config file* rather than part of the library.
- **config form** — how the studio opens a *config file*: one labelled field per value with its comment beside it, instead of the text editor. Reads the file without running it and writes an edit by splicing that one value, so comments and layout survive. Falls back to the text editor for anything outside the subset.
- **asset** — a picture, sound or video in a game's working tree, under `assets/`, in three folders by what it is: `assets/sounds/`, `assets/sprites/` for a *strip*, and `assets/images/` for a picture that does not move. The folder is not decoration — the *sound player* and the *sprites library* resolve a plain name in the first two, so where a file lands is how the game finds it. Put there by a person from the studio and never by an agent: `write_file` takes text, so a helper can point the game at `assets/sprites/hero.png` but cannot create or change it. Named to agents in the file list and as `[binary: <path>, <size>]`, never as bytes.
- **project documents** — the three files an agent keeps at a project's root alongside the code: the *brief*, the *game spec*, and the *task list*. Notes for the people and agents working on the game, never part of the game itself. Nothing scaffolds them; an agent writes one when the project is worth it.
- **brief** — `BRIEF.md` at a project's root: the file map, plus any standing instructions. The one project document injected into every agent's system prompt, so it is capped at 32 KB and cut with a note rather than sent whole. A plain versioned file rather than a database column.
- **game spec** — `SPEC.md` at a project's root: what the game is and how it is meant to work — rules, controls, screens, settled decisions. An ordinary ambient file, unlike the *brief*. (Not `spec.md`, which is this studio's own design-of-record.)
- **task list** — `TODO.md` at a project's root: one task per line, written only when the list is long enough to be worth staging.
- **attached agent** — a `project_agents` row: one agent bound to one project, carrying its `chatty` flag and cooldown state.
- **chatty** — an attached agent that responds to every human message, not only to `@mention`s. (from `new-y`)
- **chat** — one conversation inside a project, and the unit a *helper* belongs to. Every project is born with two: **Just us**, which it opens on and which no helper may ever be put in, and **Building**, where they can. A game may have up to twenty; each has its own thread, its own line-up, its own cooldowns and its own pins, and a helper sees only the one it is in. Carried in the URL as `?chat=`, remembered per game in the browser. Not to be confused with a *chat project*, which is a project with no working tree — its chats are all it has.
- **crew** — everyone in the studio, in the sidebar tab of that name: the **humans** (accounts, from `GET /api/users` — names and ids, never addresses) over the *helpers*. Both belong to the studio rather than to one game, which is what puts them on one tab. A human row is a name and nothing to click: accounts are made with `npm run adduser` and by nothing in the interface.
- **helper** — what the interface calls an *agent*. Code, schema, routes, and SSE payloads say "agent" everywhere; only user-facing text says "helper", because the studio is used by kids. Do not introduce "helper" into the code.
- **fire** — one complete agent response cycle: eligibility claimed, context built, tool loop run, message and commit persisted, cooldown set. (from `new-y`)
- **context path** — a project path a human attaches to a message, handing that file's current content to the agents on that turn.
- **pinned file** — a file named by a context path on the current or previous two human turns. Offered to the context byte cap first, and named on the last user message as what the human is pointing at — never labelled inside the file block, where the label would churn the prompt cache. Priority, not exemption: a pin that does not fit is dropped and named like any other.
- **ambient context** — the rest of the working tree, sent to an agent on every fire without being asked for. Affordable because DeepSeek's window is 1M tokens; trimmed largest-first when the byte cap binds.
- **reasoning trace** — DeepSeek's `reasoning_content`. Streamed to the client and rendered collapsed, never persisted to a message and never replayed into a later request.
- **published** — a game's `projects.published` flag: it appears in the *catalog*. Not an access control — every game has always been playable by link.
- **catalog** — the page at `/` on the games origin listing published games. The only page there that is not a project's own file.
- **rollback** — putting a project's whole working tree back to how it was at an earlier commit, committed as a new commit: files restored, anything made since removed, nothing rewritten. The UI says *bring everything back*. Not `git revert` — see spec.md §5.
- **fork** — a copy of a game: its working tree and full git history under a new slug, carrying the attached agents, starting a fresh thread.
- **duplicate** — a copy of one file inside the same game, made from the open file's bar: `POST /files/duplicate`, one commit, the original untouched. A *fork* copies a whole game; a duplicate copies one file.
- **draft** — unsent composer text, held per project in the client and never on the server. It survives a re-render and a switch to another game; only sending it clears it.
- **project mutex** — the per-project promise chain that serialises write-and-commit, so concurrent agents cannot interleave git operations.
- **reporter** — the script that runs inside a game and posts its errors to the studio. Never a file in a working tree and never a tag in a game's markup: the games listener injects it, so no game carries it and no agent can lose it.
- **wrapper** — `_studio.html`: a game's own `index.html` served with the reporter and the current commit injected in front of it. Reserved in every project, used only by the studio's preview; the public plays the untouched page.
- **runtime error** — something the game said went wrong while it ran: an uncaught error, a resource that would not load, or a `console.error`. Stamped with the commit whose bytes produced it, so a fix retires it. The UI calls these *problems*.
- **scoreboard** — a game's public top-100 of `{name, score}` entries, kept in the studio's database and served by the games origin at `/_scores/<slug>` — that origin's only write route: no cookie read, rate-limited per IP, capped on every dimension, and forgeable by design because the client is the only witness. Never a file in the working tree, so a score commits nothing, restarts no preview, and never enters an agent's context. Per game it can be switched off (`projects.scores_on`): both public routes answer 404, helpers stop being told it exists, and the rows are kept. Moderated from the rail's Scoreboard tab — the list, per-row deletion, delete-all, and the switch, all on the studio origin. See spec.md §3, §6.
- **receipt** — the record behind the token note under a reply: what the fire was given (bytes per part of the context — instructions, brief, files, conversation, tool traffic) and what each request cost (cache hits, misses, output), captured at fire time because none of it can be recomputed later. Kept for every reply in `message_receipts`; the full prompt text rides along as a debugging aid held only for the newest reply in each project — the next fire takes it. Code and docs only: the UI never says "receipt", the token note simply opens.
- **API note** — the comment block at the top of a *studio library*'s file, reproduced in the preamble for each library a game holds: the engine's contract in the prompt, never its source. Read from the game's own copy, so it matches the held version; capped at 2 KB. See spec.md §4.
- **shed** — a one-line `[studio]` user-role note the tool loop appends mid-fire once DeepSeek's replayed reasoning pile costs more to carry than to drop: a user turn closes the tool-call chain, so the API stops re-billing the accumulated trace (spec.md §8, §14). Never persisted — loop messages never are — and counted on the *receipt*.
- **view** — what the rail is showing, as three things a URL can carry: which tab, which file, and which version's changes (`?tab=`, `?file=`, `?version=`). `urlNow` writes one from the state and `applyView` sets the state from one; they are inverses, and every view is its own history entry. Not a stored thing — the URL is the only place it lives. See spec.md §6.
