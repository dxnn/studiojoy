# Glossary

- **game project** — the unit the studio is organised around: a chat thread plus a versioned working tree of files, playable at a public URL. A `projects` row with `kind = 'game'`. (formerly: *conversation*, in `new-y`)
- **chat project** — a `projects` row with `kind = 'chat'`: no working tree, nothing on disk, nothing served on the games origin. One *chat* and only ever one — no `Humans only` in front of it and no second to switch to — which takes helpers, wears the project's name and is renamed with it. A database from before that comes forward as one room. (formerly: chat, before a project could hold several conversations)
- **tint** — the per-speaker colour wash on a message bubble. Hue and blob placement are derived from a hash of the speaker's id, warm for people and green-to-blue for agents; it carries no meaning beyond identity.
- **slug** — a project's `[a-z0-9-]` identifier. Immutable, and simultaneously the directory name under `GAMES_DIR` and the path segment on the games origin.
- **working tree** — a project's on-disk directory. The source of truth for file content; there is no files table.
- **project path** — a validated relative path inside a working tree. Validation rules are the app's main security boundary.
- **studio access** — `users.studio_access = 1` on an account still in (`deleted = 0`): the `In the studio` / `Games only` toggle in Studio settings, and what every account from before the bit was. It is what gets you into the studio, and it lets you *read* everything: every game, every version, every conversation — login, the *crew* list, *mention*s and authorship all mind it, history does not, and turning it off ends the person's studio sessions the way removal does. Off, the account is a *player account*. What it no longer carries is the right to change somebody else's game — see *author*. (formerly: simply having a `users` row.)
- **player account** — an account with *studio access* off: what approving the *waiting list* makes, never an admin. It signs in on the games origin — its own `player` cookie over `player_sessions`, 90 days where studio sessions never expire, worth nothing on the studio origin — and its name is what the *scoreboard* writes. Inside the studio it is only a row in the admin panel, whose toggle can make it either kind. The code says **player** (`server/players.js`); the panel says `Games only`.
- **waiting list** — `signups`: what the *catalog*'s public `Ask to join` writes, and never an account by itself. The panel shows the undecided rows only when there are any; an admin's `Let them in` makes the *player account* with the password chosen at sign-up, `Turn away` says no. ⚠️ Both decisions are columns kept on the row — who and when, shown nowhere — never a DELETE, and the form answers the same 202 whatever an address already is, so it discloses nothing (spec/ §11).
- **removed** — `users.deleted = 1`: an account taken out of the studio. Every door is shut — login, the session, the *crew* list, being named by a *mention*, being added as an *author*, the admin panel — and every row is kept, so their messages still carry their name and the games they author are still theirs. ⚠️ Never a DELETE, and their address stays theirs: `npm run restoreuser -- <email>` clears the bit and gives back the same person, which is why `adduser` answers a removed address by pointing at the restore instead of making a second account. ⚠️ There is no interface for it and no route: `npm run deluser -- <email>` is the only way out. Adding an account is an everyday thing and lives in the panel; taking one out is rare, has consequences no click can show, and is worth walking to a terminal for.
- **admin** — `users.admin`: may run the studio — add an account, rename one, set a password, set a daily *allowance*, hand out the bit, and set the studio-wide budget. The first account has it and the studio keeps at least one. It says nothing about games: an admin has no more right to somebody's game than anybody else, which is what *author* is for.
- **allowance** — `users.daily_tokens`: what one person's helpers may spend in a day, set in the admin panel. A reply is billed to whoever asked for it — the newest human message in that chat when the fire started — so running out stops that person's helpers and nobody else's. Null is no allowance of their own; the studio-wide budget is the wall around everybody either way. Within a tenth of it, the token note under the newest reply says how much is left — your own numbers, from `/api/me`, never in a message.
- **author** — somebody who may change a game: the person who made it, plus anyone an author has added (`project_authors`). A game keeps at least one. An author decides who else is one, and whether the game is *open* — being able to work on a game is not the same as deciding who does. Two things sit outside the rule on purpose: anybody in the studio may talk in a game's human-only *chat*, and anybody who can read a game may *fork* it. ⚠️ The interface says **editor** everywhere — the `Editors` button, the dialog behind it, every message a person reads — and the code, the database and the wire say `author`. Same rule the studio's *helper* follows for an agent.
- **open** — `projects.open_edit`: this game is the whole studio's to change. What a game a person makes starts as, forks included — this is a studio of people who trust each other, and a game nobody else may touch should be somebody's decision rather than what happens to everything by default. Turned off in the `Editors` dialog, and a game that is off wears a *lock*. Not the column's default, which stays 0: an existing database already has the column and SQLite cannot change a default afterwards, so creation states the value.
- **lock** — 🔒 in front of a game's name, when that game is not *open*: only its editors can change it. A status and not a control — it does not light up and it does not click, and what it says is set in the `Editors` dialog, where the sentence beside the switch spells it out.
- **studio origin** — the authenticated listener (`PORT`) serving the SPA and `/api`.
- **games origin** — the unauthenticated listener (`GAMES_PORT`) serving only game files. A separate origin so LLM-written game code cannot read a studio response. On two ports of one hostname the session cookie still travels there, so it is a read boundary, not a write one — spec/ §7.
- **config file** — a file under `config/` in a game's working tree: plain `const NAME = value;` declarations with a comment on every value, holding the numbers and words a person tunes without reading code. One batch per file — `play.js`, `world.js`, `look.js`, `words.js`, `controls.js`. Loaded by the game like any other script; agents may change them freely, keeping the comments.
- **pixel editor** — how a PNG opens, full width in the centre under Pics or Code (formerly: in the rail): the picture itself, ready to draw on, with Draw, Erase, Fill and Eyedropper as icons, a brush width, a *palette*, and undo and redo a gesture at a time — each step holding the pixels it changed rather than a copy of the picture. It saves itself two seconds after a stroke, into the *pending commit*; there is no Save.
- **look** — the four colours a game lends the studio, named in `LOOK` in its own `config/look.js`: `primary` (the game's voice — its buttons, its name, your own messages), `accent` (the second colour: helper names, file chips, edges), `highlight` (a score or a version number, and nothing else) and `deep` (the dark behind them). Set on the shell as `--look-primary` and friends while that game is open, so the chat pane, the composer, the *mode* row and the rail wear the game being made; the sidebar keeps the studio's own cyan, which is what stops the studio from looking like whichever game is open. ⚠️ Each value reaches a style attribute, so it is checked first — no colon, semicolon, `url()` or `var()` — and a value that fails leaves the studio's default standing. Same file as the *palette*, read in the same pass.
- **originator** — the person who made a game: `projects.created_by`, `originator` on the wire as a flag about *you*. Display only until 2026-09-02; now the one account that may archive the game (spec/ §11) — not its *author*s, not an *open* game's whole studio — and only while it is out of the games list. Archiving is one way from the studio; `npm run unarchive -- <slug>` brings a game back, at a terminal, the way `restoreuser` does an account.
- **palette** — `PALETTE` in a game's `config/look.js`: thirty-two colours, two rows of sixteen, that the *pixel editor* offers. Not a fixed list — the chosen square is both what the pencil draws with and what the colour box and the eyedropper write into, so it is built up rather than picked from, and each change is a commit on the game. A game with no `look.js` is shown the studio's own thirty-two, and the first change writes the file. The only way a PNG opens — there is no second, look-only view, because it showed the picture at exactly the same size. Up to 1024 a side, RGBA rather than a palette of indexes, so an uploaded picture opens losslessly and is saved at the size it arrived.
- **sound editor** — how a `.wav` the studio wrote opens — in the rail under Hear, or in the centre under Code: a preset, a shape, and a row of sliders with a comment on each, saved back over the same file like any other *asset* two seconds after the last slider (no Save). The same surface makes a new sound and changes an old one, because the file carries its own *sound note*; `+ Make a sound` asks nothing at all — it writes a blip into `assets/sounds/` under a name nobody has to think of and opens it, because the name is a better question once you have heard it. Plain arithmetic in `public/sound-maker.js` — no Web Audio — so the bytes it plays are the bytes it saves. A sound from anywhere else opens as the player, with the reason underneath. (formerly: sound maker, which was a dialog.)
- **sound note** — the numbers that made a sound, written into the `.wav` they made: a JSON comment in the file's `LIST`/`INFO`/`ICMT` chunk, which every player skips and an audio editor shows. It is what makes a sound editable a week later — samples cannot be turned back into sliders — and it travels with the file through a rename, a copy or a clone, which a note beside the file would not. Nothing in it is trusted: a value no slider could produce is the default instead.
- **studio library** — the studio's own code, copied into a game under `studio/` and listed in its **manifest**, `studio/studio.json`, as name-to-version. Copied rather than shared or submoduled so the repository stays complete: clone it, publish it, and it still runs. Two rules make it a library — ⚠️ a helper may read it and never write it (`isLibraryPath` in `paths.js`), and it is named to an agent rather than sent, so an engine costs the ambient context a line instead of its source. The *input module* is the first one. Every game is born holding the library — creation scaffolds it in one commit — and is kept current by the *sweep*; there is no update path from inside the studio. See spec/ §4.
- **sweep** — `npm run sweep` (`bin/sweep.js`): brings every game's *studio library* forward on the machine holding the games — libraries a game lacks are added, held copies raised to the current version, seeds and everything else of the game's own never touched. One commit per game that needed anything, authored as the studio (`studio@gamestudio.local`), readable and revertable like any other version. ⚠️ Safe only under the **compatibility law** (spec/ §4): a library version N+1 must run every game that ran N; if the law must break, the fleet is small enough to fix by hand. Skips archived games (they catch up after reopening) and any manifest newer than the studio's own.
- **game template** — a starter tree copied into a new game at creation ("Start from" in the New game dialog): a whole small game with its remixable heart in a config file, a pre-written *brief* and *game spec*, and the library tags already in place. From then on the files are the game's own — no version, no updates, editable everywhere — unlike a *studio library*. Source: `public/game-templates/` (distinct from `public/templates/`, the library seeds). Its `index.json` entry also names its **heart**, the file the studio opens the new game on when the template brings no *editor* — the one a person edits to change the game. Its key becomes the game's *game type*, so the template is what a type starts from. Three exist: the *arcade* game, the quiz and the *visual novel*. ⚠️ All three fix their own *control scheme*, which is why only a *blank start* is asked how it is played. See spec/ §4.
- **game type** — `projects.type`, a *game template*'s key (`visual-novel`, `quiz`, `arcade`): what a template grows into once the studio knows what a game *is*. A type decides which *editors* the centre pane offers — `public/game-types.js` is the one registry — and what the preamble tells a helper about the game. Null is a free-form game and stays the default. Set at creation from the template and copied by a fork; a column and never a file in the tree, so no `write_file` can change which editors somebody sees. ⚠️ A game from before the column is marked `''` and answered once from its own tree — the type whose heart file it holds — the answer written back, null included (spec/ §3).
- **editor** — a surface a *game type* brings to the centre pane: one *mode* each, in the row between Chat and Code, taking the whole pane the way the chat does — the sidebar and the rail as they are. Which is showing is `S.mode`, in the URL as `?mode=<id>` (formerly `?edit=`), remembered per game; the chat behind it is still the chat, filling, and a mention lands as a *mark* on the Chat pill until it is pressed. The *story editor* is the first; a type may bring several. ⚠️ Same word as the interface's name for an *author* — an editor *of* a game is a person, an editor *in* the centre is a tab — kept because the plan chose it (ideas/vn-builder.md).
- **mode** — one of the pills in the row over a game's centre pane, and the one thing the centre shows at a time (spec/ §6, `S.mode`). Which modes a game has comes from its *game type* (`modesFor` in `public/game-types.js`), in order: `chat` (the chat's own pills and helpers over the thread), then the type's editors — **Write** for a *visual novel*, **Questions** for a quiz — then `pics` (every picture in the game by what it is — for a visual novel *Characters* over *Places*, for every game its sprites, its pictures and the *reserved images* — as cards, one opening full width in the *pixel editor*), `hear` (sounds over music, a row each, the open one's *sound editor* or player in the rail), `controls` (the *control scheme* and each verb's bindings), `code` (the file list with the open file's editor under it), `versions` (every past version of the game, one row a commit, each opening its diff — its own mode now, no longer a section of `share`) and `share` (the link and whether it is *published*, then Scoreboard and Achievements as one page). A chat project has only the chat and no row. ⚠️ **The pills are named for the senses and the code is not** (decided 2026-09-04, on trial): the buttons read **Speak**, **See**, **Hear**, **Touch**, **Taste**, **Recall**, **Smell**, in that row order, while every id, route, comment and spec paragraph — and the preamble a helper reads — keeps `chat`, `pics`, `hear`, `controls`, `code`, `versions`, `share`. Same split as *author*/editor and `agent`/*helper*, with one price the others do not pay: a helper still says "change it in Controls" to somebody looking at a pill that says Touch. The two editors keep their plain names. Everything a *person* reads says the pill's word; everything else says the code's. There is no Play: the preview lives in the rail and only there. Carried in the address as `?mode=`, which replaced `?tab=` and `?edit=` (both still read). Leaving a mode lands the *pending commit*.
- **blank start** — `public/game-templates/blank/`, the page and *brief* a game made without a *game template* is born with. The page: the game's name, one line saying to ask a helper, and the script tags for the libraries it holds — all but the *input module*, because a plain page has nothing to steer and a phone would otherwise show a stick and buttons over it; the seed `config/controls.js` is still there for the day a helper wires controls in. Not a template — it is not in their `index.json`, because "A blank page" is already the New game dialog's empty choice, and it is the one page there that is not copied byte for byte (`{{name}}` becomes the game's name). It exists because a game with no `index.html` is nothing the *games origin* can serve, so a new game answered `{"error":"not found"}` until a helper had written one. The brief beside it is copied byte for byte, and is the only place that says which tags that page carries, that the *input module* is missing from them on purpose, and that the seeded *control scheme* is a default with four alternatives a word away. Read from `publicDir` like every other scaffold, so a `public/` without it writes nothing.
- **visual novel** — the second *game template*: scenes of spoken lines and choices, DOM rather than a canvas, and no coordinates anywhere — which is why it came before the point-and-click adventure, whose spot rectangles need eyes a helper does not have. `config/story.js` is its heart and opens as the *story editor*. Ships empty — no cast, no scenes — so the first thing an author meets is the *guide*'s first question; a scene with nothing in it is the end, so an empty story plays as its title and then The End. Uses two libraries, *sound* and *screens*, and neither input nor sprites.
- **story editor** — the *visual novel*'s *editor*: `config/story.js` as the centre pane, the **Write** *mode* in the row over it (formerly: the Story tab beside the chats), TyranoBuilder's three regions inside it. The scene strip down the left — every *scene* with its problems and its tail, then the *cast* — is the editor's own navigation; for the selected scene the *stage* over the *steps*, and the editor bar under them: the whisper (*Saved* / *Saving…*), *Show the text* (the file as plain text in the rail, which is the only way it opens there now), *Try this scene* (the preview at the game's own `?scene=`). No Save: it saves itself two seconds after an edit and sooner on the way out of a field, a scene, the editor or the game, into the *pending commit* (formerly: an explicit Save, until 2026-09-02). Regenerates the file rather than splicing (it is that file's authoring surface; byte-identical on an untouched save); a file that outgrows the shape keeps its tab, which says why and offers the text. Renaming a scene brings every way in with it, and renaming a mood renames the picture and every line said in it. It still reads the whole graph and the game's file list at once, which is what a form could not do: a scene nothing leads to, a way out that points at a scene that is gone, a *switch* nothing sets, a picture or portrait the game does not have, a mood the cast does not have. An edit a save could not land is parked per game and comes back while the file is unchanged. The strip also holds the **title screen** — the title and the line under it, which are `config/words.js`'s two lines, spliced back by the same save the way the *config form* writes so the rest of that file stays its own — and a scene's head row has *Duplicate*: a copy right after it, for a choice that keeps the player where they are, since the shape has no lines after a choice. (formerly: a form in the rail.)
- **guide** — the *story editor*'s questions, one card at a time over the *stage*, each answer an edit to the story that selects what it changed: who the main character is, how they look, where the story starts, what that looks like, what happens first, who else is there, then where each scene leads — and every scene the story points at but has not filled comes round as its own question, saying how it is reached. Deterministic: `nextQuestion` in `story-editor.js` reads the next question off the story and the game's files, the same facts the checks read, so its only state is what the author set aside (*Later*, per game in prefs, cleared by *Ask me again*), and it works on a new story, a half-built one or one hand-edited for a week. An ending is a scene with lines and no way out answered *The story ends here*. Pictures come from it five ways — the *shelf*, Draw, Upload, *Make one for me*, a plain *stand-in* — and where words are wanted there is a *fill*. The whole Mila story is one click, *Or put in an example story*, while the story is still empty. Never says "prompt" or "model" (ideas/vn-builder.md §4).
- **stand-in** — a picture the studio makes so a story never gets stuck on art, in two rungs. The **plain stand-in**, *A plain card for now*, costs nothing and never fails: a flat card in the game's *look* — the deep colour, a primary border, a round face for a person, the name in white — drawn on a canvas and saved as the PNG the story already expects, 128×128 for a face and 480×270 for a place. The **drawn stand-in**, *Make one for me*, is a *microhelper*: it asks for a flat SVG at that size in the game's own colours, and the browser probes it in an `<img>` — no scripts, nothing loaded — and rasterises it to the same PNG, so the *pixel editor* opens it like any other picture. ⚠️ The probe is built at the size it should be, or an SVG with only a `viewBox` draws as nothing. An answer that will not draw falls back to the plain card and says so; a refusal writes nothing and lets its banner stand.
- **fill** — *Fill it in for me* on the *guide*'s lines card: a sentence about what happens back as lines of the *scene*, in the story's own cast keys, inserted where typed ones would go and committed by Save like everything else. A *microhelper*, so it is billed to whoever pressed and leaves no message. ⚠️ A speaker the cast does not hold comes back as the story narrating — a fill must not leave a line said by nobody for the *story editor*'s checks to flag straight back.
- **microhelper** — a fixed-purpose helper the studio ships rather than an *agent* row somebody makes: one request built from what is on screen, one answer, nothing kept — no chat, no message, no receipt, no eligibility, no cooldown, and for these two no tools either. Through the same two token walls a reply goes through, billed to whoever pressed the button (spec/ §6, §10). The *fill* and the drawn *stand-in* are the first two; the achievements helper is the candidate that named the idea.
- **standard set** — `public/story-art/`: pictures and sounds an author can put into a *visual novel* without drawing, listed in its `index.json` (file, kind, name, who made it, licence, and who/mood on a portrait) and copied into a game when picked — one file, one commit, no history and no link back. Studio-side rather than in the template tree, which is copied whole into every new game, so a set of any size would bloat every repository and a game holds exactly the art it uses. Picked from the *shelf*; an *example* copies its own art in by name, landing by kind — backgrounds to `assets/images/`, portraits to `assets/sprites/`, sounds to `assets/sounds/`, keeping the file name. It holds 33 portraits and 9 backgrounds, all CC0: the example story's own, 30 animal faces by Kenney, and 6 pixel-art scenes by Stealthix — two styles that do not match, kept because the alternative was three faces. `test/story-art.test.js` is what keeps it honest as it grows, with rules loose enough for real art: a background is landscape, and ⚠️ a portrait must not measure a whole multiple of its own height, or the *sprites library* reads it as a *strip* once it is copied into `assets/sprites/`. Read-only and in this repo; the half people here add to is the *studio collection*, and the half nobody chose one by one is the *big set*.
- **big set** — `public/big-set/`: 1,775 CC0 pictures mirrored into this repo by the *pull*, offered on the same *shelf* as the hand-picked *standard set* and the *studio collection*. Where that set is 42 pictures somebody chose, this is the large machine-gathered half, and its whole point is that a kid types a word and gets a picture with no network, no key and no third party deciding what is safe. One kind, `sprite` — one thing on a transparent background, landing in `assets/sprites/`; a background or a portrait belongs in the standard set, where somebody looked at it. ⚠️ The interface says **thing** (`Pick a thing`, `+ Find a thing to put in`) and the code says `sprite`, the same split *editor*/author keeps. Each entry carries `tags` the other two halves have not — the pack's subject, or a silhouette's common word — which is the only reason it is searchable: `Fish red` comes back for *underwater* and `Triceratops` for *dinosaur*, and neither word is in either name. ⚠️ The shelf draws 120 at a time; 1,775 at once is a second of layout for a grid nobody scrolls. Two sources, both CC0: 16 Kenney packs (1,685) and PhyloPic (90), which are the studio's only dinosaurs. See spec/ §6.
- **pull** — `npm run pullart` (`bin/pullart.js`): what writes the *big set*, run on a machine that can reach the sources the way the *sweep* is run on the machine holding the games, and never in `npm test`, which has no network. ⚠️ Safety is the **source list** and not a filter: every pack is one author's CC0 art, safe by what it is, added by somebody who looked at it, with no moderation queue behind it and none intended. It writes `public/big-set/` whole — so a re-run is how the set changes, git says what moved, there is deliberately no way to pull one source, and a source that fails outright stops the run rather than writing what the others managed. Nothing is resized (that would cost a PNG decoder and encoder in a repository with no dependencies): anything over 512 a side, over 128 KB, shaped like a *strip*, or named a word and a number (`tile_0044`) is skipped instead, and `asPng()` in the browser fits a picture when somebody picks it. `bin/unzip.js` is how it reads an asset pack without a dependency.
- **studio collection** — `collection_art`: pictures people in the studio have added themselves, offered on the same *shelf* as the shipped *standard set* and picked the same way. `Duplicate…` on a picture's row under Code puts one in — the collection is one of the three places its dialog offers (formerly its own `Copy…`, before that `Share to studio…`, each a button of its own); the ✕ on your own thumbnail takes it out, confirmed first. ⚠️ The bytes are in the row, not a directory: a game's tree recovers itself from git and the shipped set is in the repo, but a picture somebody drew here exists nowhere else — and `npm run backup` is a `VACUUM INTO` of the database and nothing more. ⚠️ **No licence is recorded and none is asked for** — whoever drew it keeps their copyright, the shelf says *made here by* and stops (spec/ §3, decided 2026-09-02, revisit on TODO.md). ⚠️ Taking one out is a real delete with no Versions behind it, safe only because picking *copies* the bytes into a game.
- **shelf** — how the *standard set* is picked from: the pictures of the kind being asked for, because it is the only answer that is somebody's actual drawing. A dialog with a filter — a grid of every picture of that kind, found by name. Three places it opens from: a row that scrolls sideways across the top of the *guide*'s picture card; `Pick a face…` on a mood's `···` in the *story editor*'s person inspector, which asks *Replace \<name\>'s \<mood\> face?* first when a face is already drawn there, and skips straight to the shelf when there is nothing yet to lose; and `+ Pick a face from the shelf` / `+ Pick a picture from the shelf` in the *Add a picture* dialog. ⚠️ The first two copy the bytes to the path the *story* expects rather than the set's own — the set says what a picture looks like, the story says what it is called, so "Mila, worried" lands as `ben-normal.png` when that is the face being asked for; from *Add a picture* there is no such path to expect, so it lands under a fresh name of its own (`assets/sprites/` or `assets/images/`, counted up past any collision) rather than overwriting anything. Who made it and under what licence ride the tooltip and the banner. Pictures only: a sound has *+ Make a sound*, which beats a shelf of stock ones. A scene's own Picture field and a picture's own card under Pics no longer offer the shelf directly — swapping either in one click made undoing a drawn picture too easy; adding shelf art as its own file first is the deliberate way in now.
- **step** — one row of the *story editor*'s scene: the scene itself, its picture, its music, one of its lines, one of its *sound step*s, or its exit. Selecting a step opens it in its row and puts what the player would see at that moment on the *stage*. Not in the URL, so not a history entry — the scene is (`?scene=`), the step inside it is not.
- **sound step** — an entry in a *scene*'s `lines` that is only `{ sound: "page" }`: a noise at that point in the scene rather than something to read. It plays the moment it is passed and the story carries straight on, because waiting for a tap would leave the box empty for a beat; one written after the last spoken line plays as the scene is left. Lines and noises are one list, so a noise drags in between two lines and out again. ⚠️ A scene-level `sound:` is the older shape, meaning "at the start": read as a sound step in front of the lines and never written back, so saving an old story moves it into the timeline — and since a *game template* is the game's own code with no sweep behind it, an existing *visual novel* needs its `js/story.js` brought forward by hand first.
- **stage** — the *story editor*'s picture of the selected *step*, drawn by the studio from the unsaved model rather than by the game: the scene's picture, the line's portrait and speaker, the words along the bottom, and on the exit the choices, the go or the end (`stageFor`, pure and tested). Close to what the player sees and not the thing itself — *Try this scene* shows the real one. Its pictures are object URLs cached by path, dropped when a `files.changed` names them.
- **scene** — one screen of a *visual novel*: a `picture`, optional `music`, and `lines` read from the top — each `{ who, mood, say }`, or just `say` for narration, or a *sound step*. `music` is a whole path under `assets/music/`, looped behind the scene and quieter than a noise, and it keeps playing into the next scene naming the same track rather than restarting. Then exactly one of three: `choices` (each `{ say, go }`, optionally `set` or `need`ing a *switch*), `go` to carry straight on, or neither, which is an ending. Its key is its name and is shown; the point-and-click adventure will use the same word.
- **cast** — `CAST` in `config/story.js`: who can speak, each with a name and a list of moods. A mood is a picture — `assets/sprites/<who>-<mood>.png` — so a cast key is wiring fixed when the person is made and never renamed, while the name people read is free to change. The interface says **Characters** — the Characters cards under Pics, one per cast member wearing their first mood, whose inspector holds their name, note and moods (decided 2026-09-02, ideas/calm-shell.md; the strip in Write still says People) — the code, the file and the wire say `cast`.
- **switch** — a thing a story remembers: a *choice* turns one on with `set`, and a choice that `need`s one is only offered once something has. One-way and forgotten when the story starts again. Shared with the point-and-click adventure when it is built, in place of the `flip` its sketch had — toggling is rare and reads as a puzzle.
- **quiz editor** — the quiz's *editor*: the **Questions** *mode*, which is `config/questions.js` while it keeps the quiz shape — the whole game as a form — questions, answers wired to endings, endings — no code shown, saving itself like the story does, each row with its `···`. Regenerates the file rather than splicing (it is that file's authoring surface; byte-identical on an untouched save), and falls back to the *config form*, then the text, once the file outgrows the shape. Ending keys are internal wiring, never shown. It reads the whole quiz too, the way the *story editor* reads the whole story: an ending no answer counts toward, one only a single answer feeds, an answer left pointing at an ending that is gone, a question with fewer than two answers.
- **sprites library** — `studio/sprites.js`, the third *studio library*: `Sprites.draw(ctx, "hero", x, y)` draws `assets/sprites/hero.png`, animated when the file is a *strip*, with `scale`, `flip`, a pinned `frame`, and a shared clock advanced by `Sprites.tick()`. No registry: the name is the file, the shape of the picture is the declaration. Still loading draws nothing; missing warns once.
- **strip** — a PNG whose width is a whole multiple of its height: square frames side by side in one file, played in order by the *sprites library*. Made by `+ Draw a picture` with a frame count, or uploaded. Opens in the *pixel editor* one frame at a time — frame buttons, a live looping preview, Copy/Paste frame, a toggleable **ghost** of the frame before, tools clipped to the open frame — with "Whole strip" to draw across everything under a frame-boundary overlay. Any other shape is a single picture.
- **sound player** — `studio/sound.js`, the second *studio library*: `Sound.play("laser")` plays `assets/sounds/laser.wav` — what the *sound editor* saves — with a pooled player per shot so rapid fire overlaps instead of dropping, plus `loop`, `stop` and `mute`. A missing file or a blocked autoplay is one console warning, never an error. Its API note is its file header.
- **input module** — `studio/input.js` in a game's working tree, the first *studio library*: one way in for the keyboard, a game controller and a touchscreen, for one player or two. `Input.update()` once a frame, then `held`, `pressed`, `released`, `axis`. Unlike the *reporter* it is a file the game carries — added from the studio, in the history, cloned with the repo — and what each button does lives in `config/controls.js`, which is the game's own *config file* rather than part of the library.
- **screens library** — `studio/screens.js`, the fourth *studio library* and the first presentational one. `Screens.hint()` returns the how-to-play line as a string, worked out at call time from `config/controls.js` and the device — key names on a keyboard, the *control scheme*'s own shape on a touchscreen, controller buttons folded in when one is plugged in — so it is never wrong on the device it is read on; `WORDS.howToPlay` in `config/words.js` replaces it verbatim. `Screens.title({ onStart })` is the phone-fit title screen — name (`WORDS.title`, else the page title), tagline, one focused Start button, the hint — and with a `score` it is the game-over screen in the *look*'s highlight with Play again, listing under the score what the run won (the *achievements library*'s awards since the last game over, as *Won this run*); every part carries a `screens-` class for the game's own css, and it returns `{ close }`. `Screens.chips({ Score: 12 }, { hint: true })` is the HUD strip: cheap to call every frame, each call says the whole strip in order, labels are the game's words, and taps fall through to the game. A value is a number, a *meter*, or a node the game built itself which the strip places once and never touches again; ⚠️ only a value with a digit in it wears the highlight, because `Guns · Cannon` in gold is the colour losing its meaning. `{ hint: true }` ends the row with the how-to-play line, left out where the game is too narrow for it. Once *fit* has said where the game is the row is placed against it — in the letterbox band above the game when the band can hold it, over the top of the game when it cannot — and ⚠️ that placement measures the row, so it never runs in the per-frame path: only when the row gains or loses a chip, when the window or the game moves, and when a `ResizeObserver` on the row says it can be measured again, which is the case a game closing its *own* screen creates. It also carries the *snippets* — `board`, `rows`, `signin` — and the two calls behind them, `Screens.me()` and `Screens.post(score)`. While a title or game-over screen is up the body wears `screens-open`, so the input library's drawn controls step aside, latches drop and the HUD hides; the Start button also reaches Input as one frame of `start`, so a game that polls `Input.pressed("start")` starts from it by touch. ⚠️ Every rule it injects is written `body :where(…)` and so weighs exactly one element selector, which is what makes a game's own stylesheet win: a game's `.screens-name` (0-1-0) beats it, a game's `button {}` (0-0-1) ties and loses to the injected sheet being later, and a game's `* { margin: 0 }` (0-0-0) loses outright. A cascade layer was tried first and is worse than nothing — unlayered beats layered at *any* specificity, so a game's reset flattened every margin on the screen (spec/ §4). `HIDDEN` in `config/controls.js` names the verbs the hint leaves out — the ones that make the game rather than play it. It carries its own two typefaces (Space Grotesk and Space Mono, OFL, beside the library under `studio/`), so a game asks nothing of a font host. Anything missing is an empty string or a quiet no-op, never an error.
- **snippet** — a piece of a screen the *screens library* builds and the game places: a DOM node, wearing `screens-` classes like everything else, usable inside `Screens.title()` or anywhere in the game's own page. Three exist. `Screens.board({ limit, around })` is the *scoreboard* — it asks `/_scores` itself, fills in when the answer comes, marks the rank given as `around`, and when that rank is past the shown rows adds the four above and four below it, numbered where they really are rather than from 1. `Screens.rows({ Rocks: 42 })` is a label-and-value list; ⚠️ its values are not gold, because a count is a number but not a score. `Screens.signin()` says who is playing or offers the link to the *catalog*, since a score only goes on the board under an account's name. `title()` composes them: `board: true` adds the board, and `post: true` beside a `score` puts the run on the board and shows where it landed.
- **fit** — `Screens.fit(el)`, the *screens library*'s answer to how big a game is on the screen, called once at boot with the canvas or the box holding it and its overlays. It takes the game's shape from the canvas' own `width`/`height` attributes and gives it the smallest of three widths: the cap (the canvas' own width, or `max`), what the window is wide, and what the window's *height* can pay for at that shape — the third being the one every game left to itself forgot, which is how a fixed 8:5 rectangle came off the top and bottom of a phone held sideways. ⚠️ Written **inline**, the one place the library overrules a game rather than yielding to it: the rule it replaces is normally `#wrap { width: … }`, an id, and nothing the library can write beats an id — so a game that calls fit says nothing about its own width, and a game that wants a different answer does not call fit. ⚠️ The height term is `100dvh` with a `100vh` line before it, since on iOS `100vh` is the window with the toolbars *gone* and a game never scrolls to earn them; the older line is what a browser that cannot parse `dvh` keeps. It publishes `--screens-fit-top`, `-left`, `-width` and `-height` on `:root`, which is how the HUD knows where the game is and how a game's own css can put something in the same place without measuring it again.
- **meter** — a *chip* whose value is a bar as well as a number: `Screens.chips({ Risk: { value: 43, max: 100, text: 43/100 } })`. The fill is the *look*'s highlight, gold like the number it draws twice — ⚠️ which is the rule kept rather than broken, since a meter is a number. Past the top is the top and under nothing is nothing, so a game cannot draw a bar off the end of its track. It exists because the alternative was a game leaving the library to hand-roll a whole HUD around one bar, and the game that did came off a phone screen for its trouble.
- **moment** — something the game says has happened, through `Moments.say("name", value)` on the exact line where it happens: a level gained, a run over, the final score, an ending reached. A slug-shaped name (`[a-z0-9-]`, up to 40) and a value that is a number, a piece of text up to 100 characters, or nothing, which is heard as `true`. A fact, never a request for a prize: the game publishes and whoever cares subscribes — the *achievements library* today, and anything else that listens, because underneath it is one `CustomEvent("moment")` on the window, so nothing has to know the library exists to hear it. Templates will say theirs out of the box.
- **moments library** — `studio/moments.js`, the fifth *studio library*: `Moments.say()` and `Moments.on()`, with the validation in front of them — a name or value outside the shape is one console warning per name and is dropped, so saying a moment every frame is fine. No register, no init, no list of moments to declare; nothing in it knows what an *achievement* is.
- **achievement** — one thing a player can earn in a game, defined in the game's own `config/achievements.js` (seeded empty into every game): an immutable slug `id` — ⚠️ the earned rows are keyed by it, so renaming one takes it away from everybody — a `name` (≤ 60), a `how` line in the player's words (≤ 200), an optional `icon` (one emoji, the reaction cap of 32 bytes), and `when`: a *moment* and one test on its value — `atLeast`, `atMost`, `is` (compared as text), or `times` said this page — or no test, for the moment happening at all. No `when` means only `Achievements.unlock("id")` in the game's code grants it. Earned is forever, per signed-in player, kept by the studio and never in the working tree. Up to 50 per game, and an entry outside the shape is skipped with one warning.
- **achievements library** — `studio/achievements.js`, the sixth *studio library*: reads `ACHIEVEMENTS`, asks the *games origin* once what this player already holds, listens for every *moment* a rule names, and the first time a rule is met — or `unlock()` is called — posts the unlock and shows a **toast** at the top of the screen under the HUD chips: icon, name and how, in the game's `primary` and `accent` (⚠️ never the `highlight`: gold stays a number). Signed out the toast still shows, with a line saying to sign in on the front page to keep it, and nothing is stored; a missing file, an unknown id or a dead network is one console warning, never an error. Each award is also said on the window as an `achievement` event, which is how the *screens library*'s game-over screen lists what the run won. `Achievements.mine()` is the list with `got` for a trophy screen. Wears `achievements-` classes and `body :where()` rules like the *screens library*, so the game's own css wins.
- **achievements editor** — the rail's **Achievements** tab, beside Scoreboard: `config/achievements.js` as a list while it keeps the *achievement* shape, one open in its own row — name, how to get it, icon, and a "Happens when" row (the *moment*, a test, a value) — no code shown. Regenerates the file with the seed's comments rather than splicing; a file that outgrows the shape keeps its tab, which says why and offers the text. Under Files the file opens as plain text and nothing else, so one surface writes it — the *story editor*'s rule. The id is derived from the name once and never editable. Two structural reads: how many players hold each one (`GET /api/projects/:slug/achievements`, studio origin) painted in place, and a rule waiting on a moment the game has not been *seen* to say — the moments the *reporter* has forwarded this session, offered in the moment box. `Take it out` confirms first and says who keeps what they earned. Explicit Save with `if-match` and an `achievements-conflict` dialog on a 409; unsaved edits parked per game like the story's. The model layer is `public/achievements-editor.js`, shared with the server through `public/achievement-shape.js`; the tab is `public/achievements-form.js`. (formerly: how `config/achievements.js` opened under Files.)
- **control scheme** — `SCHEME` in a game's `config/controls.js`: the physical shape of the game — what hands do — which decides what a touchscreen shows. Six exist: `buttons` (drawn buttons under both thumbs: the `touch:` directions as a big pair or an arrow pad on one side, every other `touch:`/`toggle:` name climbing a diagonal from the other corner — and what no `SCHEME` means, so every game from before the word plays this way untouched), `one-button` (a tap or a click anywhere, `touch:screen`, nothing drawn), `swipe-tap` (four flicks and a tap as `swipe:` bindings — moments, not states, read with `pressed()` and never `held()`), `stick-buttons` (a floating analog stick, `stick:left` …, beside the drawn buttons — what *arcade* starts as), `dual-stick` (a move and an aim stick; `stick:move` / `stick:aim` are held while one is pushed, which is how a touchscreen fires and starts), and `none`, the **null controller** — no controller at all, because the game's own buttons on the page already work everywhere a mouse, a finger, the Tab key or a screen reader does. Nothing drawn, no surface installed, ⚠️ and the one shape that leaves the browser its keys and its page: a prevented keydown on Space is a click the browser then never sends to the button under the focus. The *screens library* says nothing for it either — a button says what it does. The verbs stay the game's own words; the scheme fixes what they can be bound to. Thumbs are tracked by geometry, so a thumb rocks between neighbouring buttons without lifting and every button wears an invisible hit halo; `BUTTON_SIDE = "left"` in the same file mirrors any layout, sticks included. Each scheme is a preset seed under `public/templates/`, whose `index.json` is the **registry**: the words New game shows, the seed each scheme starts from, and the validation list. Chosen when the game is made — New game's **How is it played?** — and changed afterwards in *Controls*, which is the difference between it and a game's type; the default is `none`. ⚠️ A request names a scheme by key and never by path. A *game template* may fix its own (`scheme` in `game-templates/index.json`, `none` for both that ship) and then the question is not asked; an explicit one still wins. Deferred: point-and-click, and the focus-cycling half of the null controller — a controller driving a `none` game's own buttons, which needs a heartbeat of its own because a page of buttons has no frame loop (ideas/control-schemes.md).
- **Controls** — the mode of the centre pane where a game's `config/controls.js` opens (the pill says **Touch**; see *mode*): the *control scheme* as one wide row per shape the studio offers (the *arcade* family opening into its three manners under it, one open at a time), then a row per verb with its bindings. The row the game wears is cyan and is not a button. Picking one writes `SCHEME` and nothing else — ⚠️ never the bindings, whose left-hand words are the game's own and are in its code by name, so the panel says what the new shape has no room for instead, with *Take it out* in each one's `···`. A verb opens in the row it belongs to, one at a time, into a row per binding — the chip, what it is in a player's words, and *Take it out* in its `···` — over three ways to add one: a key is **pressed** rather than picked out of a list, and a controller button or something on the screen is a select of the shape's own vocabulary, so a shape can only be given what it draws. A drawn button's row carries its name and *it latches* (`touch:` ↔ `toggle:`); a key or pad button stays momentary. `BUTTON_SIDE` and `STICK_DEADZONE` sit under the shape where it has them, ⚠️ written into the file the first time one is used. Verb names are read-only for the same reason as the bindings. Shape-locked like the *quiz editor*: `CONTROLS` must be a group of players, each a group of things to do, each **one line** of bindings; anything else falls back to the *config form* or the text with the reason said, and a declaration the panel does not know is named rather than hidden. `public/controls-editor.js` is the model, shared with `npm test`; `public/controls-form.js` is the panel.
- **arcade** — the family of *control schemes* held like a games machine: `stick-buttons`, `buttons` and `dual-stick`, the three that draw something under a thumb. A **family** is a grouping in the interface and never a word in a file: New game offers Arcade in one line and seeds the family's first manner, and which manner it actually is — a stick and buttons, buttons only, two sticks — is narrowed down afterwards. `SCHEME` is always one concrete scheme, because a file claiming to be arcade would not say which shape a phone gets. `offer` and `families` in `public/templates/index.json` are where the grouping lives. ⚠️ One-button and swipe-tap are deliberately *not* in it: the family means a control drawn under your thumb, and those two draw nothing — widen it to mean "arcade-feeling" and it swallows everything but the null controller, which is not a grouping worth having.
- **arcade template** — the third *game template*: a canvas, a loop, and a ship holding the bottom of the screen while meteors fall (`public/game-templates/arcade/`). It is the *game shape* written out — `Screens.fit` at boot, `Screens.chips` for the HUD with the charge bar as a *meter*, `Screens.title` for both screens, `Input.update()` first in every frame, `Moments.say` where the thing happens — so a game made from it starts out doing what the preamble asks rather than being told to. Its *heart* is `config/play.js`: every number that changes how it feels, in one file, for somebody who will not open `js/game.js`. It fixes `buttons` as its scheme, so New game does not ask. ⚠️ It ships no `config/controls.js` — the scheme seed writes that — so the verbs it asks `Input` for must be the seed's own; `test/arcade-template.test.js` holds the two together, along with every call above. Its key makes `arcade` a *game type*, which brings no *editor* of its own: the numbers open in the *config form* under Code. Listed as "An arcade game", in the same voice as "A quiz" and one word away from the *arcade* scheme family it uses.
- **toggle** — a `toggle:NAME` binding in `config/controls.js`: a drawn touch button that latches — tap on, tap off, `held()` the whole time between, worn visibly (bright ring) while latched. For a verb a thumb would otherwise have to hold forever — autofire, an engine — so turn, thrust and fire can all happen at once on two thumbs. `key:`/`pad:` bindings on the same verb stay momentary. A latch drops when the window blurs or a Screens screen opens; sliding onto a toggle never flips it, only a deliberate tap does.
- **config form** — how the studio opens a *config file*: one labelled field per value with its comment beside it, instead of the text editor. Reads the file without running it and writes an edit by splicing that one value, so comments and layout survive. Falls back to the text editor for anything outside the subset.
- **asset** — a picture, sound or video in a game's working tree, under `assets/`, in four folders by what it is: `assets/sounds/` for a short noise, `assets/music/` for a whole track, `assets/sprites/` for a *strip*, and `assets/images/` for a picture that does not move. The folder is not decoration — the *sound player* and the *sprites library* resolve a plain name in `assets/sounds/` and `assets/sprites/`, so where a file lands is how the game finds it; a picture that does not move and a track are named by their whole path instead, a track because its ending varies. An upload is measured before it is filed: a picture's shape says whether it is a strip, and audio over ten seconds is music rather than a noise — a guess the upload dialog shows before sending and its folder box overrules. Put there by a person from the studio and never by an agent: `write_file` takes text, so a helper can point the game at `assets/sprites/hero.png` but cannot create or change it. Named to agents in the file list and as `[binary: <path>, <size>]`, never as bytes.
- **reserved image** — one of three optional picture names at the root of a game's tree that the studio dresses itself with rather than the game: `chat.png` tiles behind the conversation, `hero.png` backs the bar over it and the game's card in the *catalog*, `icon.png` sits before the game's name in the sidebar. Root, not `assets/` — a sprite that happens to share a name must not become the studio's dressing. Person-made like any *asset*; a game without one wears the studio's own look. Offered under **Studio dressing** in Pics — the one section that shows with nothing in it, because a *name* is what makes these three work and no pane could otherwise say they exist.
- **project documents** — the three files an agent keeps at a project's root alongside the code: the *brief*, the *game spec*, and the *task list*. Notes for the people and agents working on the game, never part of the game itself. Every game is born with a *brief*; a *game template* ships a *game spec* too, and nothing ever scaffolds a *task list*.
- **brief** — `BRIEF.md` at a project's root: the file map, plus any standing instructions. The one project document injected into every agent's system prompt, so it is capped at 32 KB and cut with a note rather than sent whole. A plain versioned file rather than a database column. Scaffolded at creation and written thereafter by whoever changes the tree: the preamble says what the studio is and the brief says what *this game* is — including which parts of the *game shape* it deliberately does not follow, and why.
- **game spec** — `SPEC.md` at a project's root: what the game is and how it is meant to work — rules, controls, screens, settled decisions. An ordinary ambient file, unlike the *brief*. (Not `spec/`, which is this studio's own design-of-record.)
- **task list** — `TODO.md` at a project's root: one task per line, written only when the list is long enough to be worth staging.
- **attached agent** — a `project_agents` row: one agent bound to one project, carrying its `chatty` flag and cooldown state.
- **chatty** — an attached agent that responds to every human message, not only to `@mention`s. (from `new-y`)
- **mention** — an `@name` in a human message, matched in `server/mentions.js` against the normalised name or a prefix of it — so `@Level` reaches Level Designer and `@Robin` reaches Robin Fox. One parser, three effects: a *helper* it names becomes eligible to answer this turn, a helper it names who is not in the *chat* is **called in** — a `chat_agents` row, waiting-to-be-called rather than *chatty*, ⚠️ never into a chat that refuses helpers and never past the ten-per-chat cap — and a person it names gets a **mark**, a `mentions` row unseen until they open the chat it was said in. Never for the person who wrote it. Clicking a human in the *crew* list inserts their handle into the composer; nothing an agent writes ever calls anybody in or leaves a mark.
- **mark** — the small cyan flag on a game, a chat project or a conversation pill: the `@n` badge, how many messages there have *mentioned* you and not been read, or — nothing there to count — a plain dot once anything at all is unread there. Per chat, so reading one conversation clears only that one, and one person's marks are never another's — `POST /api/projects/:slug/chats/:id/seen` is what clears both together (`chat_reads`, one row per person per chat, the newest message id they have read there), and it is the client that calls it when a chat is opened. Cyan because it is the studio talking to you rather than the game; ⚠️ never gold, which stays a score or a version.
- **reaction** — an emoji a person puts on a message: a pill under the bubble with a headcount, everybody's names on its tooltip, and `+` beside it offering a fixed twenty. Yours to toggle, on anybody's message in any game, archived included — a reaction is talk about the work, not a change to it. One `message_reactions` row keyed `(message_id, user_id, emoji)`, so the key is the toggle; never a message, never in an agent's context, and no agent can leave one. The UI never says "reaction" — the chips speak for themselves, the same rule as *receipt*.
- **chat** — one conversation inside a project, and the unit a *helper* belongs to. Every *game* is born with two: **Humans only**, which it opens on and which no helper may ever be put in, and **Building**, the *builder*'s room — its one seat, and no other helper may be put in it — both unconditionally, an upgraded database included: a Building that already held people's helpers keeps them and its words as `Old building`, and a fresh Building is made beside it. (formerly: Just us) A game may have up to twenty, made with `Add chat…` in the game's `···`, which is left out rather than greyed out when there is no making one; each has its own thread, its own line-up, its own cooldowns and its own pins, and a helper sees only the one it is in. Carried in the URL as `?chat=`, remembered per game in the browser. A *chat project* has exactly one and none of that furniture.
- **crew** — everyone in the studio, in the sidebar tab of that name: the **humans** (accounts, from `GET /api/users` — names and ids, never addresses) over the *helpers*. Both belong to the studio rather than to one game, which is what puts them on one tab. A human row does one thing: clicking the name drops `@Firstname` into the composer, which leaves that person a *mark* on this game. Your own name is not clickable, and nobody's is when there is nowhere to type. Accounts are still made with `npm run adduser` and by nothing in the interface.
- **helper** — what the interface calls an *agent*. Code, schema, routes, and SSE payloads say "agent" everywhere; only user-facing text says "helper", because the studio is used by kids. Do not introduce "helper" into the code.
- **fire** — one complete agent response cycle: eligibility claimed, context built, tool loop run, message and commit persisted, cooldown set. (from `new-y`)
- **context path** — a project path a human attaches to a message, handing that file's current content to the agents on that turn.
- **pinned file** — a file named by a context path on the current or previous two human turns. Offered to the context byte cap first, and named on the last user message as what the human is pointing at — never labelled inside the file block, where the label would churn the prompt cache. Priority, not exemption: a pin that does not fit is dropped and named like any other.
- **ambient context** — the rest of the working tree, sent to an agent on every fire without being asked for. Affordable because DeepSeek's window is 1M tokens; trimmed largest-first when the byte cap binds.
- **reasoning trace** — DeepSeek's `reasoning_content`. Streamed to the client and rendered collapsed, never persisted to a message or a *receipt* and never replayed into a later fire. The one time it enters a request is the *thinking cap*'s hand-on: once, as text on a user turn, within the fire that capped it (spec/ §8).
- **thinking level** — how hard one agent thinks before answering: `full`, `low` or `none` on `agents.thinking`, sent as `reasoning_effort` (`full` sends nothing, which is the API's own default). New agents start on `low`, because at `full` an ambitious request spends its whole output allowance on the trace and writes nothing (spec/ §14). The interface calls it "How much to think first"; `agents.reasoning`, the boolean this replaced, is still written and never read.
- **thinking cap** — the ceiling on one turn's trace, in characters of `reasoning_content` (`THINKING_CAP_CHARS`), applied only until that turn produces something else. Past it the stream is stopped and the same turn is asked again with thinking off and the trace handed on as notes — measured (spec/ §14): dropped, the retry under-delivers; handed, it follows the design — and in the *builder*'s room a first-turn cap hands it to the *sizing* instead. The backstop against a fire that would otherwise spend nine minutes thinking and produce nothing.
- **sizing** — the one call ahead of a *fire* in the *builder*'s room: the fire's own system prompt, no tools, thinking off, a JSON answer of `small` — one change, or a remark — or `big` with a plan of 2–6 *pieces*, through `complete()` like a *microhelper* and warming the fire's cache prefix (spec/ §8, §14). The ask rides the last user message after everything else on it. A capped *reasoning trace* is handed to it as notes, ahead of the ask; so is what a small ask did before it outran its budget — the files it changed and its *working* (`begunNote`), with the ask then sizing the rest rather than the whole; a paused plan's pieces still to do ride in it too, and its answer then carries on (`resume: true`), sets aside (`resume: false`) or replaces (`big`) that plan.
- **piece** — one item of a *sizing*'s plan (`{title, files, what}`), run as one *fire* whose last user turn is a `[studio]` row naming the request, the plan, what the earlier pieces said they made and this piece alone — "do only this piece, then one line" — at thinking `none`, with the plan's named files whole and the tree for the rest, and a short message row and a commit (`Builder: piece i of N — title`) of its own. The plan is a message of kind `'plan'` over a `plans` row and shows as a checklist, the **plan card**, moved along by `plan.update`; a message mid-plan pauses it after the running piece. Named from the banners' "ask for one piece at a time".
- **builder** — the studio's own *helper* (`server/builder.js`): the one `agents` row with `builtin = 1`, nobody's to edit, delete or put in a chat — not listed on the Crew tab, not called in by an `@` — with its words, model and thinking the code's, written onto the row on every open. Its room is every game's `Building` (`chats.builder`), which takes no other helper the way `Humans only` takes none (`assertBotsAllowed`), and which a new game is answered with; the chip has no `···`, the room no `+` and no rename. One request at a time: *sizing*, then a fire at its own level (`low`) for a small ask — under a budget of its own, `SMALL_TURNS`/`SMALL_TOOL_CALLS` (6/12), named in the room's preamble; one that uses it up keeps what it did and hands the rest back to the sizing as a plan, the room's only continuation — or one *piece* at a time for a big one. Not a *microhelper*: it keeps message rows, commits and *receipt*s. (formerly: the *starter helper*, `studio_state.default_agent_id` — an admin-picked row that joined every new game's `Building`; the column stays unread.)
- **published** — a game's `projects.published` flag: it appears in the *catalog*. Not an access control — every game has always been playable by link.
- **catalog** — the page at `/` on the games origin: the studio's front door, and the only page there that is not a project's own file (`server/catalog.js`). The wordmark over the *published* games as cards — each wearing its hero picture and its board's best score in gold, and for whoever is signed in their own *personal best* (gold too, a score) and their trophies against what the game defines (`★ 3 of 7`, not gold: a count is not a score) — plus sign-in, `Ask to join` and sign-out, which is where a *player account* lives its whole studio-side life. Under each card, *Scores & trophies* opens that game's *players page*. *Featured* games lead the page, then the rest ordered by *play count* — neither number shown. The studio's own dark, always. ⚠️ It holds a password form on the origin that serves LLM-written game code, so this page alone is sent with `frame-ancestors 'none'` and `COOP: same-origin` (spec/ §7).
- **featured** — the *catalog*'s first up to four cards: games with a commit in the last 7 days, reshuffled on every load rather than pinned to a fixed order. Fewer than four such games means fewer featured cards — never padded out with older ones. Everything past them is ordered by *play count*.
- **play count** — `projects.play_count`, a running total raised once per load of a game's own `index.html` on the games origin — its assets don't count, and neither does the studio's own *wrapper*. Orders the *catalog*; never shown, the same as the trophy tally on a card.
- **players page** — `/:slug/_players` on the games origin, the second studio-authored page there (`server/catalog.js`): everybody's numbers for one game — one *personal best* per person, the game's *achievement*s with who holds each, and under those the board's top 100 — the viewer's own rows marked in cyan, which is the only thing the `player` cookie does on it. Nothing about scores while the game's *scoreboard* is off; the trophies stay, because earned is forever. Reached from *Scores & trophies* under a card in the *catalog*; a plain 404 for anything that is not a game's. Static and scriptless. (ideas/front-page-players.md, rung 2.)
- **rollback** — putting a project's whole working tree back to how it was at an earlier commit, committed as a new commit: files restored, anything made since removed, nothing rewritten. The UI says *bring everything back*. Not `git revert` — see spec/ §5.
- **fork** — a copy of a game: its working tree and full git history under a new slug, carrying the attached agents, starting a fresh thread.
- **duplicate** — a copy of one file, made from the file's `···` on its row under Code, its dialog asking where: this game (`POST /files/duplicate`, one commit, the original untouched), another game (`POST /files/import`, formerly behind its own `Copy…`), or — a picture — the *studio collection*. A *fork* copies a whole game; a duplicate copies one file.
- **draft** — unsent composer text, held per project in the client and never on the server. It survives a re-render and a switch to another game; only sending it clears it.
- **project mutex** — the per-project promise chain that serialises write-and-commit, so concurrent agents cannot interleave git operations.
- **pending commit** — a project's one open window of saves waiting to become a commit (`server/files/pending.js`, spec/ §5): whose saves, which paths, and a 45 s idle timer. A save (`PUT /files/*path`) is written at once and opens or joins the window; the window lands as one commit — `create a.txt`, `update 3 files`, under the saver's name — on the timer, on the client saying it is leaving (`POST /commit`: another game, another scene, the tab closing), and ⚠️ always before anybody else writes to the tree, before a helper's *fire*, and before a move, delete, duplicate, copy in, restore, *rollback*, *fork* or archive. Every commit that lands, from whichever route or turn, is a `version.new` on the stream; `files.changed` fires on the write. Reads never land it. While it is open the *wrapper* wears `<sha>:<n>` for the n-th save, so the *runtime error*s a preview reports have a version to be filed against. Only a person's saves open one; a helper's turn commits as it always did.
- **reporter** — the script that runs inside a game and posts its errors — and, since achievements, its *moment*s, the latest value per name a few times a second — to the studio. Never a file in a working tree and never a tag in a game's markup: the games listener injects it, so no game carries it and no agent can lose it. The studio paints both in place under the preview, never through `render()`: the game restarts on every commit, and a report that rendered would render a report.
- **wrapper** — `_studio.html`: a game's own `index.html` served with the reporter and the current version — the commit, or `<sha>:<n>` while a *pending commit* is open — injected in front of it. Reserved in every project, used only by the studio's preview; the public plays the untouched page.
- **runtime error** — something the game said went wrong while it ran: an uncaught error, a resource that would not load, or a `console.error`. Stamped with the version whose bytes produced it — the commit, or the save on top of it while a *pending commit* is open — so a fix retires it. The UI calls these *problems*.
- **scoreboard** — a game's public top-100 of `{name, score}` entries, kept in the studio's database and served by the games origin at `/_scores/<slug>`. Reading it is everybody's; posting takes a signed-in *player account* or studio person, and the name on the row is the account's — whatever the body says is ignored, so a game from before the sign-in works the moment its player signs in. Rate-limited per player, capped on every dimension, and the *score* still forgeable because the client is the only witness to the run — what the sign-in ended is the name being anybody's. Each post also raises the poster's *personal best*. Never a file in the working tree, so a score commits nothing, restarts no preview, and never enters an agent's context. Per game it can be switched off (`projects.scores_on`): both public routes answer 404, helpers stop being told it exists, and the rows are kept. Moderated from the rail's Scoreboard tab — the list, per-row deletion, delete-all, and the switch, all on the studio origin. See spec/ §3, §6.
- **personal best** — `personal_bests`: one row per person per game, their best score ever, raised (never lowered) in the same transaction as every scoreboard post. It exists because the board keeps the best 100 *runs* — a best that fell off the board would otherwise be gone. Shown as *your best* on your own card in the *catalog*; everybody's, side by side with the top 100, is the players page planned in ideas/front-page-players.md.
- **receipt** — the record behind the token note under a reply: what the fire was given (bytes per part of the context — instructions, brief, files, conversation, tool traffic) and what each request cost (cache hits, misses, output), captured at fire time because none of it can be recomputed later. Kept for every reply in `message_receipts`; the full prompt text rides along as a debugging aid held only for the newest reply in each project — the next fire takes it. Code and docs only: the UI never says "receipt", the token note simply opens.
- **working** — what a helper said on the way to its reply: every turn's words but the last, kept in `messages.working`, shown behind a `Working` panel above the bubble beside `Thinking` (fetched on open, `GET /api/messages/:id/working`), never in the body and never replayed into a later *fire* (spec/ §3, §8). The last turn's words are the **reply** and are `messages.body` — what the thread shows, what heads the commit, what history replays. The live entry folds each turn's words into the same panel as the turn ends (`agent.tool`). Named from the schoolroom "show your working". The dots under a live reply wore the class `working` before this; they are `busy` now.
- **API note** — the comment block at the top of a *studio library*'s file, reproduced in the preamble for each library a game holds: the engine's contract in the prompt, never its source. Read from the game's own copy, so it matches the held version; capped at 3 KB. See spec/ §4.
- **game shape** — the part of the preamble that follows the *API note*s and says a game is expected to *make* those calls, not merely that it can: the title and game-over screen are one `Screens.title` with the score as the difference, how big the game is on the screen is *fit* and never width css of its own, the HUD is `Screens.chips` — *meter*s and the game's own nodes included — a frame begins with `Input.update()`, choosing a *control scheme* is the game's own job, and `Moments.say` goes on the line where the thing happens. ⚠️ Gated on `studio/studio.json` line by line, exactly as the notes are: a game without a library is told nothing about it. Written because six notes read as six optional conveniences, and a helper that read all six still hand-rolled a title screen. A *brief* is where a game says which of these it deliberately does not follow — a DOM quiz builds its own screens. See spec/ §8.
- **shed** — a one-line `[studio]` user-role note the tool loop appends mid-fire once DeepSeek's replayed reasoning pile costs more to carry than to drop: a user turn closes the tool-call chain, so the API stops re-billing the accumulated trace (spec/ §8, §14). Never persisted — loop messages never are — and counted on the *receipt*.
- **view** — what the studio is showing, as things a URL can carry: the centre's *mode* — `?mode=` for any but the chat, with `?scene=` for the story editor's selected scene when it is not the first, Code's open file or Versions' filter as `?file=`, and Versions' open one as `?version=`; or `?chat=` for a conversation other than the one the project opens on, never both (formerly `?edit=` and the rail's `?tab=`, both still read). `urlNow` writes one from the state and `applyView` sets the state from one; they are inverses, and every view is its own history entry. Not a stored thing — the URL is the only place it lives. See spec/ §6.
